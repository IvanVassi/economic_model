# Сложная народнохозяйственная модель

Динамическая имитационная модель национальной экономики: 13 секторов производства, 22 социальные группы,
консолидированный бюджет, валютная биржа и Центральный банк, внешний долг, розничный рынок, демография по
67 годовым когортам. Модель задана графом из 7993 блоков и исполняется собственным интерпретатором на Python. К ней прилагается веб‑интерфейс: 51 экран, 573 рычага
управления, графики показателей во времени, задание программ управления (графиков рычагов).

## Установка и запуск

Нужны Python 3.11+ и NumPy (pytest — для тестов). Зависимостей у интерфейса нет.

```bash
git clone https://github.com/IvanVassi/economic_model.git
cd economic_model
pip install numpy pytest
python3 -m ui.server            # → http://127.0.0.1:8765
```

Откройте адрес в браузере. Порт и файл модели можно задать: `python3 -m ui.server --port 9000 --mdn SNHM.MDN`.

## Как работать с интерфейсом

**Шапка.** Модельное время в годах; кнопки счёта на 0.1 / 0.5 / 1 / 5 лет — модель продолжает с текущего
момента, рычаги можно менять между отрезками («управление без остановки модели»). «⟲ сброс» возвращает исходное
состояние. «шкалы оригинала» растягивает оси до шкал, заданных автором модели. Переключатель варианта:
**patched** (по умолчанию, с правками, см. ниже) или **эталон** (файл как есть).

**Левая колонка — 51 экран** по группам: макроэкономика, бюджет, финансы и внешнеэкономическая деятельность,
производство и труд, секторы, социальные группы, инвестиции и ресурсы, демография и оборона. Значок ⚙ —
на экране есть панели управления.

**Панели с рычагами.** Ползунок или числовое поле; диапазон взят из модели. Изменённые относительно исходного
значения рычаги подсвечены. Кнопка «📈 график» открывает редактор программы изменения рычага во времени:
точки (год, значение), режим «ступенчато» или «плавно», быстрое задание «плавно к X за N лет с текущего момента»,
предпросмотр. До первой точки рычаг не меняется, после последней держится её значение. Активные графики
перечислены под доской и переживают сброс — эксперимент можно повторить с t = 0.

**Переключатели режимов** (радиокнопки): денежная эмиссия, расходы бюджета по доходам или по плану, возврат долгов
поставщикам, поставки должнику, политика ЦБ «коридор / траектория».

**Графики.** Каждая серия подписана с текущим значением. Если величины на одном графике различаются на порядки,
график делится на части с собственными осями. Шаг оси времени подстраивается под горизонт.

**С чего начать** (методика автора): экран 9 — ступенчато изменить одну налоговую ставку на 25–50 %, проследить
на экранах 1 (макропоказатели), 8 (исполнение бюджета), 19–44 (секторы и группы), затем вернуться в исходное
состояние и пробовать две ставки, расходы бюджета (экраны 7–10), параметры секторов (4, 45–48), внешнеэкономические
условия (11–15). Заканчивать анализом социальных групп: уровень и качество жизни, социальная напряжённость.

## Как работать с моделью через LLM

Репозиторий устроен так, чтобы языковая модель (Claude Code, Codex и т. п.) могла исследовать и гонять модель
без интерфейса.

1. **Что читать сначала.** `PLAN.md` — архитектура, семантика 17 типов блоков, карта диапазонов номеров,
   статус работ. `docs/spec.md` — содержательное описание подсистем и связей между операторами.
   `docs/mapping.md` — соответствие описания и файла, шаблоны сектора и социальной группы, все переменные
   состояния, рычаги по экранам. `export/model_blocks.csv` — все 7993 блока с формулами; `export/model_screens.txt` —
   какие блоки стоят на каких экранах.

2. **Найти блок.** Номер = сектор·1000 + офсет (например, `#11039` — цена с НДС сектора 11 «пищепром»;
   социальная группа сектора k — `#k802…#k899`). Поиск по имени: `grep -i "норма прибыли" export/model_blocks.csv`.
   Формула и входы блока: `python3 -c "from mdn import load; b={x.idx:x for x in load('SNHM.MDN')}[1057]; print(b.name, b.formula(), b.inputs)"`.

3. **Прогнать сценарий из кода.**

```python
from sim.session import Session
S = Session('SNHM.MDN')                 # variant='patched' по умолчанию, 'reference' — эталон
S.set_lever(14, 30.0)                   # НДС 20 → 30 %
S.set_schedule(15, [(1.0, 30.0), (3.0, 40.0)], mode='linear')   # налог на прибыль плавно к 40 % за 2 года
S.switch(299, 298, choose_a=True)       # расходы бюджета по доходам, а не по плану
S.run(5.0)                              # 5 лет, ~2 с
print(S.value(155), S.value(44), S.value(151))       # ВВП, дефицит, уровень жизни
ts, M = S.series([380, 231, 501])       # траектории: качество жизни, безработные, курс
```

4. **Разобрать причину эффекта.** Идти от показателя к его входам (`Block.inputs`), сравнивая значения в двух
   моментах времени — так найден, например, механизм всплеска качества жизни при повышении НДС (`PLAN.md`, этап 6).
   Скрипты `scripts/static_check.py` и `scripts/run_indicators.py` показывают согласованность семантики и таблицу
   ключевых показателей по годам.

5. **Через HTTP** (сервер запущен): `GET /api/screens`, `GET /api/screen/9`, `GET /api/series?blocks=380,231`,
   `GET /api/block?id=11858`, `POST /api/lever {block, value}`, `POST /api/schedule {block, points, mode}`,
   `POST /api/switch {a, b, choose_a}`, `POST /api/run {years}`, `POST /api/variant {variant}`, `POST /api/reset`.

6. **Правки модели** оформляются как именованные функции в `sim/patches.py` с обоснованием и нормировкой к исходному
   состоянию; эталон не изменяется. Тесты: `python3 -m pytest tests -q`.

## Варианты модели

- **Эталон** — файл как есть. Известные особенности: численность социальной группы сектора не зависит от занятости
  (уволенные остаются в группе с доходом занятых), индекс качества жизни не ограничен сверху.
- **Patched** (по умолчанию) — численность групп пропорциональна занятым, безработные перетекают в свою группу,
  индекс качества жизни ограничен. При t = 0 совпадает с эталоном, отличается только динамика.

## Сценарий «Казахстан-2025 → повышение НДС 12 → 16 %»

Пример прикладной калибровки: `scripts/kz2025.py` подбирает ставки налогов 2025 г. (НДС 12 %, КПН 20 %, ИПН 10 % и др.),
коэффициенты приведения налоговых баз (#21–#29), объём и структуру расходов бюджета, экспортные цены и трансферт Нацфонда так,
чтобы доходы и расходы государственного бюджета в % ВВП по компонентам совпали с фактом Казахстана 2025 года.
Подгоняются также рынок труда и структура населения: масштаб трудовых ресурсов секторов (безработица 4.6 %), численность пенсионеров,
работников бюджетной сферы, военных и отображаемое население (20.5 млн). Устойчивую инфляцию модель не воспроизводит, поэтому фоновая
инфляция (12.3 % в 2025 г.) задана в отчёте экзогенно, а модель даёт отклонение цен от неё.
`scripts/kz_vat_report.py` от этого состояния запускает сценарии на 2026–2030 гг. (база без реформы; НДС 16 %;
НДС 16 % с льготной розничной ставкой; НДС 16 % с сокращением трансферта Нацфонда) и собирает отчёт.

```bash
python3 scripts/kz_vat_report.py
```

Результат: [`docs/report_kz_vat.md`](docs/report_kz_vat.md) — таблицы «факт / модель», макропоказатели, бюджет по компонентам,
секторы, социальные группы, ограничения метода; `docs/kz2025_levers.json` — все изменённые рычаги; `docs/kz_vat_results.json` — сырые данные.
Чтобы получить откалиброванное состояние в интерфейсе, загрузите рычаги из JSON через `POST /api/lever` (`{"block": <номер>, "value": <значение>}`)
и выполните прогон 15 лет; повышение НДС — рычаги #14 и #19.

## Структура репозитория

| Путь | Содержимое |
|---|---|
| `SNHM.MDN` | исходный бинарный файл модели |
| `mdn/` | разбор формата: блоки, экраны, фреймы, экспорт |
| `sim/` | интерпретатор (`model.py`), сессия прогона (`session.py`), правки (`patches.py`) |
| `ui/` | HTTP‑сервер и одностраничный интерфейс |
| `scripts/` | статическая проверка семантики, прогоны, диагностика; `kz2025.py`, `kz_vat_report.py` — калибровка к Казахстану-2025 и сценарий НДС |
| `tests/` | 22 теста: формат, семантика, сессия, экраны, правки, калибровка |
| `docs/` | спецификация модели, сопоставление с файлом, таблица операторов, отчёт по сценарию НДС для Казахстана |
| `export/` | текстовые выгрузки всех блоков и экранов |
| `PLAN.md` | план работ, установленные факты, статус |
